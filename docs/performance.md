# 1.0 性能测试记录

测试日期：2026-10-10。测试环境：macOS 26.5.2，Apple 芯片 Mac，arm64 优化编译。

## 常驻开销

正在运行的正式应用在两次空闲采样中，`top` 显示 CPU 为 0.0%，内存为约 39 MB。该结果是当时的采样值，不能代表所有使用场景或长期耗电情况。

代码没有持续轮询定时器。悬浮球和菜单通过鼠标事件展开／收起，离开延迟为 300 毫秒；复制反馈 1.2 秒后恢复。

## 菜单构建与复制

采用与正式版本相同的源码和优化编译设置，使用独立测试语句文件和独立命名剪贴板。每组先构建一次菜单预热，再各重复 30 次。

菜单耗时覆盖列表重建及布局；不包含最终屏幕绘制、鼠标输入传递和完整交互响应。复制耗时包含写入测试剪贴板和设置成功反馈状态。

| 语句数量 | 菜单构建中位数 | 菜单构建 P95 | 复制中位数 | 复制 P95 |
|---:|---:|---:|---:|---:|
| 5 | 0.989 ms | 3.339 ms | 0.067 ms | 0.118 ms |
| 50 | 1.422 ms | 5.993 ms | 0.078 ms | 0.093 ms |
| 200 | 3.101 ms | 8.675 ms | 0.157 ms | 0.342 ms |
| 1000 | 11.709 ms | 13.616 ms | 0.457 ms | 0.495 ms |
| 2000 | 23.275 ms | 28.675 ms | 1.128 ms | 1.312 ms |

样本中的 P95 取排序后索引 `floor((n - 1) × 0.95)`。这是一台电脑上的局部基准，结果会受硬件、系统负载和语句内容影响。

## 当前实现边界

每次展开重建全部语句行，复制时遍历全部行更新反馈，因此开销随语句数量增加。保存语句会对全部数据编码，并原子写入 JSON。最多支持 2000 条语句，尚未进行列表缓存、完整交互延迟或长期内存稳定性测试。
